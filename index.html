Windows CLI Guide

Install & Uninstall Apps via CMD

A complete step-by-step reference and interactive command generator using Windows Package Manager (winget).

0

Open Command Prompt as Administrator

Most application installers require elevated privileges to write to Program Files and register system services.

  • Method A (Fastest): Press Win + X, then press A (Terminal / PowerShell as Admin).
  • Method B: Press Win + R, type cmd, and press Ctrl + Shift + Enter.
  • Method C: Press the Windows key, search for cmd, right-click Command Prompt, and select Run as administrator.
Note: Windows 10 (version 1709+) and Windows 11 include winget out of the box. No extra software installation is required!
1

Verify Winget & Check Package Sources

Verify that winget is working properly and inspect which download sources are configured on your system:

winget --version; winget source list
Administrator: Windows PowerShell ✓ Verified Output
Terminal Output: Winget v1.9.25200 with msstore and winget sources. Verified: 12-09-2026 21:44:01

What this output means:

  • v1.9.25200: The installed version of Windows Package Manager.
  • msstore: Microsoft Store catalog (connects to storeedgefd.dsx.mp.microsoft.com).
  • winget: The official community repository (connects to cdn.winget.microsoft.com) hosting open-source and desktop Win32 apps.
2

Search for an Application

Before installing, search the repository to find the application's unique Package Id:

winget search chrome -s winget
Administrator: Windows PowerShell ✓ Verified Output
Terminal Output: Found Google Chrome with package ID Google.Chrome (version 153.0.8010.37). Verified Search Output

Key Output Columns Explained:

  • Name: The human-readable application name (e.g., Google Chrome).
  • Id: The unique, unambiguous package identifier (e.g., Google.Chrome). Always use this exact ID for installation.
  • Version: The latest software release currently available in the repository.
  • Match: The attribute that triggered the match (e.g., Moniker: chrome or Tag: chrome).
3

Install an Application

Use the package Id to install the program. Using --id ensures you don't accidentally install an unrelated app with a similar name:

winget install --id Google.Chrome -s winget -e --accept-package-agreements --accept-source-agreements
Administrator: Windows PowerShell ✓ Verified Output
Terminal Output: Winget detects existing installation safely and checks for updates. Verified: 12-09-2026 22:15:19
Smart Duplicate Protection: If the application is already installed on your PC, winget intelligently detects it and queries whether an update is available instead of breaking existing installations.
  • --id <ID>: Unique package identifier (e.g. Google.Chrome).
  • -s winget: Forces the winget source only, bypassing Microsoft Store certificate verification failures.
  • -e: Exact string match for the package ID.
  • --silent: (Optional) Performs installation in the background without pop-up wizard clicks.
  • --accept-package-agreements: Automatically accepts publisher license terms.
  • --accept-source-agreements: Automatically accepts repository source terms.
4

View Installed Applications

Verify which version of a package is currently installed on your PC:

winget list Google.Chrome
Administrator: Windows PowerShell ✓ Verified Output
Terminal Output: Verified Google Chrome (version 153.0.8010.37) installed via winget source. Verified: 12-09-2026 22:16:25
Notice the warning? "Failed when searching source; results will not be included: msstore"
winget is resilient: even if the Microsoft Store source encounters an error, it queries remaining healthy sources (like winget) and returns your installed apps! To filter specifically by source and suppress the warning: 
winget list Google.Chrome -s winget

To inspect all programs installed across your entire PC (both via winget and traditional MSI/EXE installers):

winget list
5

Update / Upgrade Applications

Check which installed applications have newer versions available in the repository:

winget upgrade -s winget
Administrator: Windows PowerShell ✓ Verified Output
Terminal Output: Found 3 upgrades available (App Installer, Microsoft 365 Copilot, Windows Terminal). Verified: 12-09-2026 22:31:39

To upgrade a single specific application:

winget upgrade --id Microsoft.WindowsTerminal -s winget

To upgrade ALL outdated applications at once (One-Click Bulk Update):

winget upgrade --all -s winget --silent --accept-package-agreements --accept-source-agreements
6

Uninstall an Application

Remove any application cleanly using its unique Package ID without leaving registry leftovers:

winget uninstall --id Google.Chrome
Administrator: Windows PowerShell ✓ Verified Output
Terminal Output: Winget uninstall syntax, arguments (--id, --name), and aliases (remove, rm). Verified: 12-09-2026 22:39:36

Silent / Unattended Removal: Suppress uninstall prompts and remove cleanly in the background:

winget uninstall --id Google.Chrome --silent

Useful Uninstall Flags:

  • --id <ID>: Target the specific package ID (prevents accidental removal of similar apps).
  • --silent (or -h): Runs the uninstaller silently without dialog boxes.
  • --purge: Deletes all residual files and directories created by portable packages.
  • remove or rm: Shorthand command aliases for winget uninstall.

Troubleshooting & Common Errors

Error: Failed when searching source: msstore • 0x8a15005e
"An unexpected error occurred while executing the command: 0x8a15005e : The server certificate did not match any of the expected values."

Why this happens: By default, winget checks both the community repository and the Microsoft Store (msstore). When on a corporate proxy/VPN, behind antivirus HTTPS scanning, or when local store certificates are stale, the TLS handshake for msstore fails with error 0x8a15005e.

Fix 1 (Instant): Specify -s winget to bypass msstore

winget install --id Google.Chrome -s winget

Fix 2: Reset and update winget sources

winget source reset --force && winget source update

Fix 3: Disable the problematic msstore source permanently

winget source remove msstore

Fix 4: Direct PowerShell Chrome installer fallback (no winget needed)

$installer = "$env:TEMP\chrome_installer.exe"; Invoke-WebRequest "https://dl.google.com/chrome/install/latest/chrome_installer.exe" -OutFile $installer; Start-Process $installer -ArgumentList "/silent /install" -Wait; Remove-Item $installer
Error: No sources match the given value: -e
"No sources match the given value: -e • The configured sources are: msstore, winget"
Administrator: Windows PowerShell ⚠ Verified Error
Why it happens: Omitting the source name after -s causes winget to treat -e as the source name. Syntax Resolution

Fix: Always place the source name (e.g., winget) directly after the -s flag: 

winget install --id Google.Chrome -s winget -e
Error: Installer failed with exit code: 0x80072ee2 : unknown error
"ERROR_INTERNET_TIMEOUT • Network connection timed out while downloading dependencies or packages"
Administrator: Windows PowerShell ⚠ Verified Error
Why it happens: Windows timed out (0x80072ee2) downloading runtime dependency (Microsoft.UI.Xaml.2.8), or the application is currently running. Verified: 12-09-2026 22:38:03

How to fix:

  • Fix 1 (Retry): Timeout errors are often temporary connection spikes. Re-running the command after a few seconds usually succeeds.
  • Fix 2 (Close in-use app): If updating Windows Terminal while running inside it, close it and run the update command from standard Command Prompt (cmd.exe).
Error: 'winget' is not recognized as an internal or external command

If your Windows machine doesn't have winget installed or enabled yet:

  • Open the Microsoft Store, search for App Installer, and click Update or Install.
  • Alternatively, download the latest .msixbundle release from the official GitHub Winget Releases.
Error: 0x80070005 (Access is Denied) / Installer failed with exit code 1603

This indicates insufficient administrative permissions.

  • Relaunch Terminal or PowerShell by pressing Win + X → Terminal (Admin).
